1. 先读 `PROJECT.md`，确认实际产物、任务源、现有规则和基线；不要从旧聊天推测当前进度。
2. 使用固定版 [临时团队操作手册]({{GUIDE_URL}})，版本 `{{GUIDE_REF}}`。只读本次职责相关路径，不默认重组全项目。

4. 当前任务源见 `PROJECT.md`。无有效任务分配者先申请，不抢单；分配、修订、run_id、结果与证据保存在同一任务。

6. 完成前回填产物、验证、假设、未完成项和影响。提交不等于接受，代码合并不等于现实验收。
7. 现有更具体的业务约束继续有效。不要为了套模板覆盖已有文件、重复状态或无关改动。

总监首轮须补齐真实项目说明、唯一任务源及当前任务，推进首个可验证动作并给出成果入口；只读手册或复制空模板不算启动。先查资料，只简短确认会改变目标、交付用途、授权或导致较大返工的缺口；常规技术细节自行判断。分工不等于必须派出成员，先比较本人办理、内部子 Agent 与独立可见聊天的实际收益。

离线执行：从任务必要材料取得可访问的同版手册副本；只有远端链接且不可联网时报告缺口，不将未读取视为已读取。个人环境路径不随公开项目发布。
