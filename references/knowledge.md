# 索引、日志与方法迭代

## 信息归属

- 业务目标、实现、实验、原始验证和经验正文留在业务项目。
- 协作资产库只保存通用规程、模板、方法回归，以及项目／问题经验的发现索引。
- 索引不得自动收集其他项目或私有聊天。获授权且可公开的信息才登记；私有来源留在项目自己的受控索引。

本仓库公共索引位置：`registry/projects.md`、`registry/experiences.md`。没有该仓库写权限时可在业务项目提交待登记候选，由获授权维护者处理；不为此要求用户转述技术内容。

## 先检索，再复用

总监规划和执行者排错时按问题／症状查经验索引，进入原项目核对输入、条件、版本、证据与失效项。不要因为项目名相似就直接套用。

项目卡：项目目标、仓库、入口、任务源、当前状态、最后复核日期。问题卡：问题／症状、适用与不适用条件、项目正文链接、固定版本／验证入口、验证层级、失效条件、最后复核日期。

发现链接可指当前入口；用来支撑既有结论的证据优先固定到提交版本。失效链接修复或标失效，不静默换成不相干记录。

## 有选择地沉淀

只沉淀耐久、非显然、遗忘代价显著的知识。优先放测试、断言、类型、示例或局部注释；只有实现本身难表达的理由才新增经验文档。

查重后更新原条目，不复制另一个版本。经验写症状、条件、失败路径、根因、有效解法、证据、预防与失效条件；未解决问题保留为失败记录，不升级为已验证方法。

不要每次任务强制写心得，不把全部聊天收进通用 Skill，不将单个项目的约束变成全局禁令。

一次真实项目可以证明某些操作已执行，不能单凭完成就证明效率提升或因果关系。失败来自已有规则未执行时，先强化对应入口和检查时点，不另造一套平行规则。平台版本、模型、个人授权和固定时刻留在业务层；通用指南只提炼可迁移操作与适用条件。

## 一份工程记录，多种报告

任务与 PR 保存原始事实。总监按里程碑或用户请求生成一份统一技术总结，包含成果、关键原理／过程、失败原因、经验、验证边界与下一步。

对外展示从同一记录提炼并检查公开范围。每个成果主张追到任务、产物版本、证据和接受记录；区分负责人目标／判断／现实操作与 Agent 的实现。不编消耗、提效、测试结果或贡献。

## 维护这套方法

重复摩擦→提出最小改进→在新任务验证→更新方法版本与回归。重要行为变化更新 `VERSION` 和 `VALIDATION.md`，重大不兼容另作迁移说明；已有业务项目锁定原版本，升级先审影响，不强制所有项目同步。

保留成熟来源、采用范围与许可说明，不声称已引入仅被引用的框架。无需新平台就能解决的事，不先造平台。模板导致更忙时删减模板，失败若来自权限或工具则修环境，不只要求 Agent 更认真。
